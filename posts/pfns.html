PFNs [1] have emerged as powerful alternatives for tabular machine learning tasks, an area that had long resisted the advances of deep learning approaches. These models are in-context learners, pretrained on synthetic datasets produced by random structural causal models, without seeing real datasets during this phase. They learn to approximate the posterior predictive distribution of a dataset by using the training rows as context: "Based on this data, what should the prediction for this instance be?"

Although they weren't the first application of transformers to tabular data, I see them as the first real bitter-lesson-pilled approach to this domain. You can scale pretraining by generating more and better synthetic datasets, giving the models more opportunities to learn how to use context information for prediction on real-world data. Deciding what makes those synthetic datasets "better" is still something to be discussed, but at least this gives us a direction for scaling.

Beyond Prediction

Your PFN can do more than predict a target variable. Many tabular tasks involve predicting a missing piece of information: I have an explicit target variable whose value I don't know, and so I will use my super powerful PFN to estimate it. That is certainly useful, but working with data rarely ends with just a prediction. For example, we might want to understand why the model made it and what we can do with that information.

Learning to explain during pretraining

Based on that, I started working on ShapPFN [7]. Those still working in the tabular data mines have probably heard of SHapley Additive exPlanations (or just SHAP) [2]. The idea is to give each feature a contribution value for a prediction relative to a baseline.

The common way to obtain these values is by evaluating subsets of features and observing how the prediction changes when features are removed. But this ends up requiring many more model evaluations. This cost can be especially high for tabular foundation models, as the forward pass is more expensive than for tree-based models or MLPs.

Some methods try to reduce this cost for PFNs by caching and reusing computations, but we can take a different path. ViaSHAP [3] presented a way to move attribution estimation into the training phase, the model itself outputs the SHAP values for you, and the prediction is obtained by summing up those feature contributions. The training loss encourages both prediction accuracy and Shapley value consistency.

When I read the ViaSHAP paper, their method seemed like a natural fit for the PFN paradigm. With PFNs we move the cost of learning from a new dataset to pretraining, with ViaSHAP we move the cost of estimating SHAP values to the training phase.

That idea was the motivation behind ShapPFN, bringing ViaSHAP-style attribution into the PFN setting, so that the model produces feature attributions alongside its predictions.

ShapPFN

The core architecture is simple, each cell is embedded as an n-dimensional vector, and alternating layers of row and column attention allow the model to capture relationships between features and rows. After the attention layers, we decode a SHAP contribution value for each cell in a target row. The final prediction is given by summing up all contributions in the row plus the baseline term.

That architecture already gives us a way to get attributions from our model, but we need to give meaning to those attributions. To do that, we use a modified version of the ViaSHAP loss, which enforces that the model prediction when only a subset of features is available is close to the sum of the contributions assigned to those features. My changes were focused on three things:

  1. A baseline term. Using the ViaSHAP approach, the default prediction would be 0, and the feature contributions would be based on how much they move the prediction from this baseline. Instead of summing only the feature attributions, we use a baseline term extracted from the target embedding of the training rows. That term corresponds to the prediction the model would make if no information about the features in one row were available.

  2. A kernel weighting term. We use the Shapley kernel to weight the loss according to the size of each feature subset, giving our attribution loss a Shapley-based objective, rather than treating each subset size equally.

  3. What a masked feature means. There are different ways to mask a feature, and each gives you a different Shapley game [4]. There isn't one right or wrong way to define it. I chose to use the Monte Carlo estimation method used by KernelSHAP instead of the feature mean baseline proposed by ViaSHAP. For a nonlinear model, averaging predictions is usually different from predicting at the average point. Monte Carlo sampling approximates that average without evaluating every background row.

These changes also affect what we are trying to explain. There are many different ways one might reference the data, examples and model when getting an explanation, our decisions are closer to KernelSHAP than the original ViaSHAP paper, not because we agree more with KernelSHAP on what should be the basis for an explanation, but because it is the default way for most ML practitioners.

\[ f_\theta(x) = \operatorname{base}(x) + \sum_{f=1}^{F} \phi_f(x) \]

What the model predicts based on the feature contributions.

\[ \hat{f}_\theta(x^s) = \frac{1}{K}\sum_{k=1}^{K} f_\theta(x_k^s) \]

Monte Carlo sampling for a subset \(s\), averaging the prediction over multiple replacements.

\[ \bar{f}_\theta(x^s) = \operatorname{base}(x) + \sum_{j \in s}\phi_j(x) \]

Prediction for a feature subset \(s\).

\[ w_s = \frac{F-1}{ \binom{F}{|s|}\,|s|\,(F-|s|) } \]

The weighting term according to the subset and feature sizes.

\[ \mathcal{L}_{\mathrm{shap}} = \frac{1}{S}\sum_{s=1}^{S} w_s \left( \bar{f}_\theta(x^s) - \hat{f}_\theta(x^s) \right)^2 \]

The loss that penalizes disagreement.

Results

To evaluate ShapPFN performance, we measure predictive performance and KernelSHAP agreement on datasets from the OpenML-CC18 [5] benchmark. For performance, we compare against NanoTabPFN [6], which is the base of our architecture and shares a similar parameter count. A subset of the datasets was used for hyperparameter optimization (HPO) for both ShapPFN and NanoTabPFN. We also include TabPFNv2 as a stronger baseline.

Predictive Performance (ROC-AUC)
Group TabPFNv2 NanoTabPFN ShapPFN(+loss)
HPO datasets 0.851 0.823 0.815
Eval only datasets 0.876 0.854 0.855
All datasets 0.872 0.848 0.848

On the performance side we can see that we can achieve similar scores to NanoTabPFN, with a little difference on the HPO and eval datasets. This result demonstrates that using the additive architecture and the loss preserve predictive performance relative to NanoTabPFN.

As for the explanation quality we compare the attributions made by our model with the ones produced by KernelSHAP when treating ShapPFN as a black box model.

Explanation Quality and Speed
Method Time (s) Speedup R2 Cosine Spearman
KernelSHAP 610 — — — —
ShapPFN(+loss) 0.06 1364× 0.963 0.987 0.954
ShapPFN (arch only) 0.06 1364× 0.179 0.750 0.687

Times are arithmetic means across datasets. Speedup is the geometric mean.

ShapPFN(+loss) explanations closely resemble the ones given by KernelSHAP, but are produced in a fraction of the time, as we only need to evaluate the model once. Another interesting result is that the architecture-only version of ShapPFN has a low agreement with KernelSHAP, although some metrics like the cosine similarity show some form of alignment.

These results show that it is possible to have the cost of explanations amortized by using PFNs. ShapPFN can accelerate usual data science pipelines because not only you get your prediction in instants, but also their explanations. This also unlocks new doors, as an example, BorutaSHAP is a feature selection method based on SHAP values, where we need to constantly retrain and extract Shapley values from our model in order to select the best subset of features, by using ShapPFN, both the cost of training and the cost of attribution are amortized by the pretrain!

What else could a PFN learn to do?

And there are many other directions one could explore with this kind of model. Improving your TabArena score is one of them, but I'm also interested in expanding what a PFN can do with a new dataset. Explanations are one example, but what other tabular data tasks could we model as a PFN objective?
